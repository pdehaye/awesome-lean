# jongwony/epistemic-protocols: agent setup

- **Snapshot:** commit `4559c62` (2026-10-12), from `repos/jongwony__epistemic-protocols/snapshot.json`.
- **Tools targeted:** Claude Code (`.claude/`), Codex (hook dispatcher, `.codex-plugin/` per protocol), `AGENTS.md` readers. 182 agent files.
- **Files:** two audiences. *Agents working on the repo:* root `AGENTS.md` (`CLAUDE.md` points to it), one `AGENTS.md` per directory (`lean/`, `scripts/`, `docs/`, `design/`, each protocol), `.claude/rules/` (always loaded), `.claude/principles/` (loaded when needed), `.claude/settings.json`, hooks, and seven contributor skills in `.claude/skills/`. *Agents using the product:* 21 packaged `SKILL.md` files (`/inquire`, `/grasp`, `/route`, …) installed as plugins. 13 core protocols carry a Lean 4 "Definition block".
- **What agents are asked to do:** edit protocol contracts, re-derive a Lean contract (`/rederive`), run runtime evals, audit LLM-facing prose, review PRs, cut releases.
- **Build and verification:** "Run `/verify` before commits": `node .claude/skills/verify/scripts/static-checks.js .`. Lean path: `lean-contract.js check` = generate `lean/.contract/` modules from each `SKILL.md` block, `lake build --wfail`, `lake lint` (the checked-in audit), and `lake test` for audit fixtures. Any protocol change needs a `plugin.json` version bump.
- **Proof policy:** the token preflight rejects `sorry`, `admit`, `set_option`, `native_decide`, `implemented_by`, `extern`, `unsafe` and metaprogramming in blocks and `Theorems.lean`. `axiom` is used on purpose: each one is a model judgment ("a black box to the contract, yours to make"), and must have a doc comment and a `Nonempty` instance. Guarantees are "stated and proved together" in `lean/EpistemicProtocols/<NS>/Theorems.lean`.
- **Lean and Mathlib guidance:** core Lean 4 only, no Mathlib. Shared `GROUND` and `TOOL GROUNDING` sections must match `Ground.lean` / `ToolGrounding.lean` verbatim. `/rederive` warns against "premature typing": keep a judgment an `axiom` until dogfooding shows it failing. No naming or search-tool guidance.
- **Skills, commands, hooks, MCP:** contributor skills `verify`, `formal-review` (three fixed formal lenses, adversarial cross-check, one PR comment), `rederive`, `realize`, `outcome`, `encapsulation`, `release`. One PostToolUse hook on Bash adds "option-set entropy" guidance after `gh` comment fetches. No MCP.
- **Permissions and safety:** `allowed-tools` per skill (e.g. `verify`: `Bash(node *)`). Harness concerns are declared out of scope ("Harness boundary"). Posting PR comments goes "to the harness permission layer".
- **Human oversight:** `/verify` surfaces findings and the user decides; proceeding logs `[verify: n critical, m concerns acknowledged]`. `/rederive` merges "only on the contributor's instruction". `/release` leaves publishing a draft to the user. No AI-attribution rule.
- **Notable ideas:** Lean contracts live in Markdown and are extracted and built in CI; `axiom` as a documented "you judge this" slot for the model, with a `Nonempty` witness each; a Lean linter (`lake lint`) that enforces declaration policy, with fixtures that break it on purpose.
- **Lean-specificity:** medium: the Lean contract pipeline and preflight are carefully specified, but Lean is a specification language for prompts; most of the setup is about prose, plugins and evals.
- **Evidence:** root `AGENTS.md`, `CLAUDE.md`, six directory `AGENTS.md` files, `.claude/settings.json`, hooks, `editing-conventions.md`; skills `inquire`, `rederive`, `formal-review`, `verify` in full; `route`, `white-bear`, `release`, `realize`, Lean parts of `verify/references/` and `lean-contract.js`/`lean-bridge.js` in part.
