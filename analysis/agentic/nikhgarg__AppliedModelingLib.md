# nikhgarg/AppliedModelingLib: agent setup

- **Snapshot:** commit `194edcc` (2026-09-28), from `repos/nikhgarg__AppliedModelingLib/snapshot.json`.
- **Tools targeted:** Codex mainly (mentions `~/.codex/history.jsonl`, `exec_command`, GPT-5.6 "Terra"/"Sol" model choice); skills live in a root `skills/` folder, not a tool-specific path. A `.codex` entry exists in the tree but was not captured.
- **Files:** six `SKILL.md` files (their `references/` files were not captured). All configure agents working *on* this library; there is no separate product skill. `econcs-formalizer`: lifecycle router for paper formalization. `econcs-prover`: proof construction and repair. `lean-community-conventions`: Mathlib style and proof-claim gate. `ai-formalization-workflows`: lessons from published autoformalization systems. `econcs-session-insights`: mines agent traces into a private wiki. `econcs-shared-worktree`: Git leases for concurrent agents.
- **What agents are asked to do:** formalize economics/CS papers end to end: source inventory, paper-facing `Spec`s, proofs, semantic audit and closeout, library extraction, reports and dashboards, public/private release.
- **Build and verification:** narrow checks first (`lake env lean papers/<Paper>/<File>.lean`, `lake build <target>`), full build once the proof surface is frozen. `LEAN_NUM_THREADS=1`, one Lake build per worktree. A Lean panic or huge diagnostic counts as failure "even when Lean exits zero". Closeout runs `scripts/draft_semantic_preflight.py` and `scripts/closeout_reuse_plan.py` ("Execute only the returned `next_action`").
- **Proof policy:** no `sorry`, `admit`, temporary `axiom`s, `opaque` shortcuts or "broad theorem-shaped assumptions" in final code; no `native_decide` for trust-critical paper proofs. "Do not weaken a paper-facing theorem silently." Proof-claim gate: `lake build`, file imported, `#print axioms` only standard axioms, statement matches the claim.
- **Lean and Mathlib guidance:** search Mathlib, CSLib, Optlib before inventing; `exact?`/`apply?`/`simp?` as hints, then clean up. Detailed Mathlib naming and style checklist, applied only to new or rewritten code. Avoid raising heartbeats; prefer `simp only` and evaluation lemmas over broad unfolding. AI-assisted code "should not be contributed back to mathlib".
- **Skills, commands, hooks, MCP:** the six skills above; no hooks or MCP.
- **Permissions and safety:** no publishing, visibility changes or pushes to public "without explicit user authorization". No `git stash`, no `git add -A`; `work_claim.py` leases per path; no long proof work in `/tmp`.
- **Human oversight:** semantic review by a "context-isolated reviewer" that did not author the proofs; a final adversarial panel of fresh reviewers; ambiguous source readings go to the maintainer as one question. "Human review may not be fabricated or auto-closed." Protected human prose (README) is off limits.
- **Notable ideas:** independent no-history reviewers for statement fidelity, with fixed prompt templates; treating panics and runaway diagnostics as failures; path leases for parallel agents.
- **Lean-specificity:** high: proof policy, axiom gate, tactic and performance advice, and Mathlib conventions are central, though much text is about paper-audit process.
- **Evidence:** all six `SKILL.md` files (`econcs-prover` read in large part, others in full); `tree.txt` for context.
