# hawkrobe/linglib

- **Domain:** Formal linguistics: semantics, syntax, pragmatics (RSA), morphology, phonology, processing, plus cross-linguistic data.
- **Primary role:** `specification/modeling`
- **Secondary roles:** `certifier-math`, `AI-oracle/referee` (the `Eval` library scores theories against data)
- **What the kernel checks:** Full proofs of each formalized paper's predictions (~32k theorems; ~10.9k `decide` uses for finite models; 19 `sorry`), plus verdict theorems in `Eval` that compare predictions with recorded experimental results using `decide +kernel`.
- **Certified vs only expressed:** Certified: that stated predictions follow from the encoded model (e.g. RSA speaker preferences in `Studies/FrankGoodman2012.lean`), and which projection accounts are right/wrong/silent on Chemla & Schlenker 2012 data. Only expressed: the linguistic theories and data themselves; whether an encoding is faithful to the paper is not checked.
- **Output artifact:** Theorems and a "scoreboard" of theory verdicts; doc-gen site (linglib.io).
- **Author mode:** Mixed, likely heavily AI-assisted: the README calls it "an experiment in 'AI for Linguistics' using ... autoformalization". I could not inspect commit trailers (shallow clone) to confirm.
- **Translation direction:** Into Lean: paper models are hand/auto-formalized; tabular data is generated from JSON by Python (`Data/ProtoRoles/Dowty1991.lean` says it is auto-generated by `scripts/gen_protoroles.py`).
- **Creative idea:** Linguistic theories are treated like Mathlib modules with regression tests: an `Eval` library computes, as kernel-checked theorems, which registered account is correct, wrong or silent on each recorded experimental observation, so a change of verdict shows up in a PR.
- **Why Lean?:** Stated: make theories fully explicit, detect downstream breakage, and compare theories formally (README). My assessment: Mathlib's probability/measure theory (RSA kernels) and `decide` over finite models are the practical draws.
- **Notable techniques:**
  - `Eval.Verdict.of` and per-experiment `verdict_eq` theorems (`Eval/Basic.lean`, `Eval/Projection/ChemlaSchlenker2012.lean`).
  - Theory registry as an inductive with an `Accepts` dispatcher and a `Stronger` preorder (`Eval/Projection/Account.lean`).
  - RSA models as Mathlib `Kernel`s with general lemmas instantiated by `decide` on a toy domain (`Linglib/Studies/FrankGoodman2012.lean`).
  - JSON-to-Lean generated data records with page locators (`Linglib/Data/ProtoRoles/Dowty1991.lean`); per-language fragments (`Linglib/Fragments/Sinhala/Verbs.lean`).
- **Heuristic check:** the Phase 1 guess was `spec+proof`. Agree, with the addition that `Eval` makes it partly a referee between theories.
